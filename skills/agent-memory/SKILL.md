# 长期记忆（跨话题的归档摘要）

## 这些记忆是什么

用户和你聊完一个话题、隔了很久才回来时，SDK 会把**上一段对话**总结成一条记忆落盘。
所以你的记忆不是「聊天记录」，而是**旧话题的结论**。

```
$AGENT_ROOT/var/memory/
├── index.json            ← 索引：每条一行元数据（id / 时间 / 标题）
└── entries/
    ├── 20261028-1432.md  ← 一条一份，纯 markdown
    └── 20261028-1605.md
```

**最近几条记忆已经自动进了你的系统提示词**（标题 + 正文摘要）——
你开口就知道「之前聊到过什么」，不用主动查。
本技能是给「想翻更早的记忆」和「要改记忆」用的。

## 怎么用：`agent-memory` 命令（首选）

**用命令，别手改文件。** 目录布局是实现细节（`index.json` 的字段名、`entries/` 的目录名、
id 的命名规则），一变你写死的命令就全废了；而且手改文件没有「成功/失败」的语义
（路径拼错了 `rm` 也返回 0，你会以为删掉了）。

```bash
agent-memory list                       # 有哪些记忆（id / 时间 / 标题 / 字数）
agent-memory get 20261028-1432          # 读某一条正文
agent-memory search 网关                # 按关键词找（标题或正文命中，不区分大小写）
agent-memory add "用户确认：灌溉阈值按 80"   # 记一条新的
agent-memory edit 20261028-1432 "改成：阈值按 60"  # 整条替换
agent-memory patch 20261028-1432 "replace-lines 2 2 阈值按 60"  # ★ 只改某几行
agent-memory delete 20261028-1432       # 删一条
```

输出是 JSON，字段：`ok` / `id` / `title` / `chars` / `summary` / `entries` / `count`。
失败时 `ok:false` 且带 `error`，退出码非 0。

### 改记忆：整条替换 vs 按行改

`edit` 是**整条替换** —— 你得把整段正文重新打一遍。这有两个问题：
每次输出都是一次重新生成，**措辞会漂**（同一件事今天这么写明天那么写）；
而且长正文每次全量输出，token 成本高。

`patch` 只改**你指定的那几行**，其余原样不动：

```bash
# 改第 2 行（行号从 1 开始）
agent-memory patch 20261028-1432 "replace-lines 2 2 阈值按 60"

# 改第 2-3 行
agent-memory patch 20261028-1432 "replace-lines 2 3 阈值按 60\n每三天浇一次"

# 在第 1 行后面插入一行
agent-memory patch 20261028-1432 "insert-after 1 这是补充：只在晴天浇"

# 删掉第 4 行
agent-memory patch 20261028-1432 "delete-line 4"

# 按**内容**定位（锚点可能不止一处，所以整段要加引号）
agent-memory patch 20261028-1432 "replace-block|阈值按 80|阈值按 60"
```

规格里的 `\n` 表示真换行。`replace-block` 的锚点用 `|` 分隔（两边都要写清楚），
**命中多处会报错并列出候选行号** —— 那说明锚点写得不够具体，多带几行上下文即可。

改完会回一个 `diff`（哪几行被改了），对着它确认改对了没有。

### 什么时候该写 / 改

- **记**：用户明确说「记住这个」「以后都按这个来」——那就 `add`。
  别把闲聊、一次性的中间状态写进去（记忆会一直跟着你，占提示词预算）。
- **改**：归档摘要是**机器压出来的**，可能有偏差。
  用户说「那条记错了 / 应该改成 X」——直接 `edit`，别只在回答里口头纠正。
- **删**：用户说「那条别记了 / 我不想要这条记忆」——`delete`。
- **查**：用户说「上次那个…」「之前提过…」——先 `search`，再 `get`。

## 兜底：用终端读（只读，别写）

命令没注册时（宿主没启用记忆能力），文件仍然在磁盘上：

```bash
cat $AGENT_ROOT/var/memory/index.json              # 有哪些记忆
cat $AGENT_ROOT/var/memory/entries/20261028-1432.md # 读某一条正文
grep -l '网关' $AGENT_ROOT/var/memory/entries/*.md  # 按关键词找
```

`$AGENT_ROOT` 就是你的私有根（系统提示词里写了具体路径）。
**只读**。要增删改就走 `agent-memory` —— 手改 `index.json` 会让条目「看不见」
（索引坏了 SDK 会从 `entries/` 重建，但你刚写的内容可能当场丢）。

## 用记忆时的注意

- 记忆是**旧话题的摘要**，不是用户的原话。引用它时要当成「当时的结论」，
  别当成用户现在的话 —— 用户可能已经改主意了（这正是你要 `edit` 的时机）。
- 提示词里只带**最近几条**（有字符预算），更早的要自己 `search`。
- 记忆正文里**没有时间戳**（摘要刻意保持稳定），要时间就去看 `index.json` 的 `createdAt`。
- **你改完记忆之后，当前会话的提示词不会立刻变**（摘要块是这一轮开头算好的）。
  想让它立刻生效，就把改完的结论**也写进你的回答**里，别指望模型自动重读。
