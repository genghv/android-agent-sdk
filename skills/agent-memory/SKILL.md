# 长期记忆（跨话题的归档摘要）

## 这些记忆是什么

用户和你聊完一个话题、隔了很久才回来时，SDK 会把**上一段对话**总结成一条记忆落盘。
所以你的记忆不是「聊天记录」，而是**旧话题的结论**。

```
$AGENT_ROOT/var/memory/
├── index.json            ← 索引：每条一行元数据（id / 时间 / 标题）
└── entries/
    ├── 20261028-1432.md  ← 一条一份，纯 markdown
    └── 20261028-1605.md
```

**最近几条记忆已经自动进了你的系统提示词**（标题 + 正文摘要）——
你开口就知道「之前聊到过什么」，不用主动查。
本技能是给「想翻更早的记忆」用的。

## 怎么读（用终端，不要新工具）

```bash
cat $AGENT_ROOT/var/memory/index.json              # 有哪些记忆
cat $AGENT_ROOT/var/memory/entries/20261028-1432.md # 读某一条正文
grep -l '网关' $AGENT_ROOT/var/memory/entries/*.md  # 按关键词找
cat $AGENT_ROOT/var/memory/entries/*.md | head -40  # 一次看个大概
```

`$AGENT_ROOT` 就是你的私有根（系统提示词里写了具体路径）。

## 读的时候注意

- 记忆是**旧话题的摘要**，不是用户的原话。引用它时要当成「当时的结论」，
  别当成用户现在的话 —— 用户可能已经改主意了。
- 记忆**只增不改**：归档是追加的，旧记忆不会被覆盖，也不会被自动删。
- 提示词里只带**最近几条**（有字符预算），更早的要自己翻。
- 记忆正文里**没有时间戳**（摘要刻意保持稳定），要时间就去看 `index.json` 的 `createdAt`。

## 什么时候该主动翻

- 用户说「上次那个…」「之前提过…」；
- 当前话题明显和某条记忆相关（比如又在讲同一个模块）；
- 你要确认某个之前的决定还有没有效；
- 用户提到一个你「应该记得」但提示词里没有的东西。

## 记新东西吗

不用你记 —— 归档是 SDK 自动做的。你要做的是**把结论写进你的回答**，
以及在合适的时候**把旧记忆翻出来用上**。

如果确实需要留下持久信息（比如某个路径、某个约定），写到工作区的普通文件里
（`$HOME/` 下），那是你自己的笔记，和这套记忆归档是两回事。
